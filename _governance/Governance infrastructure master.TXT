## LOCATION ASSIGNMENTS

### LIVES ON SERVER ONLY — _governance/
These files are the read source for all AI agents.
Infrequently changed. Always current. Always accessible by URL.

```
All 25 governance files (00-24)
```

Claude reads these via URL.
Windsurf reads these via URL.
You upload a new version only when a rule changes.
That is rare — maybe once a week at most.

---

### LIVES ON SERVER — _operations/ (small subset)
These are the files Claude reads at the start of EVERY session.
They change daily. They must be on the server so Claude can fetch them.

```
_operations/daily/TODAY.txt              ← today's work order
_operations/daily/PRIORITIES.txt         ← current priority stack
_operations/logs/SESSION_LOG.txt         ← Claude's memory (most important)
_operations/tasks/ACTIVE_TASKS.txt       ← what's in the queue
_operations/tasks/BLOCKERS.txt           ← current blockers
```

These 5 files are what you upload at end of each day.
That is your only daily server maintenance obligation.
Everything else on this list is local.

### LIVES LOCAL ONLY — generated code staging
This is the staging gate. Code never goes directly to live server.
It passes through this gate first.

```
_generated/
    /review/          ← executor drops output here
    /approved/        ← you review and approve
    /rejected/        ← rejected with reason noted
    /deployed/        ← confirmed live on server
    /archive/         ← old deployments
```

---

### LIVES LOCAL ONLY — prompts
Reusable prompt templates for each AI and task type.
Windsurf references these locally.

```
_prompts/
    /governance/
    /builders/
    /validation/
    /analysis/
```

---

### LIVES LOCAL — commandcenter/ mirror
A local copy of the live server's PHP application.
This is what Windsurf edits.
You then upload the changed files to the live server via cPanel.

```
commandcenter/        ← exact mirror of live server
```

RULE: The live server is always the deployed truth.
The local mirror is always the working copy.
Never edit directly on the live server (exception: urgent hotfixes only).

# PART 3 — DAILY EXECUTION (THE REAL ROUTINE)

---

## MORNING — 10 minutes max

**Step 1.** Open Claude. Paste this message:

```
Good morning. Read these and produce TODAY.txt (the work order):

legaisee.com/commandcenter/_governance/_operations/daily/SESSION_LOG.txt
legaisee.com/commandcenter/_governance/_operations/daily/PRIORITIES.txt
legaisee.com/commandcenter/_governance/_operations/tasks/ACTIVE_TASKS.txt
legaisee.com/commandcenter/_governance/_operations/tasks/BLOCKERS.txt
```

**Step 2.** Claude fetches the files, reads them, produces TODAY.txt.

**Step 3.** Read TODAY.txt. If something looks wrong, ask Claude before proceeding.
If it looks right, say "Approved."

**Step 4.** Save TODAY.txt to your local _operations/daily/ folder.
Upload TODAY.txt to server at:
legaisee.com/commandcenter/_governance/_operations/daily/TODAY.txt

Done. Morning session complete.

---

## MIDDAY — execution time (varies)

**Step 5.** Open Windsurf. Paste this at the start:

```
Read these files before doing anything:

legaisee.com/commandcenter/_governance/_operations/daily/TODAY.txt
legaisee.com/commandcenter/_governance/10_EXECUTION_PIPELINE.txt
legaisee.com/commandcenter/_governance/06_MODULE_STANDARDS.txt
legaisee.com/commandcenter/_governance/05_FREEZE_ZONES.txt

Summarize the task, list files you will modify,
confirm no frozen files are touched, then wait for approval.
```

**Step 6.** Review Windsurf's pre-edit summary.
If correct: "Approved. Proceed."
If wrong: "Stop." — bring the conflict to Claude.

**Step 7.** Windsurf works. You watch.
Red flags that mean STOP IMMEDIATELY:
- It mentions a file not in TODAY.txt
- It says "while I'm here I'll also..."
- It creates a file you didn't ask for
- It suggests a framework or pattern not in the system

**Step 8.** When Windsurf finishes, it gives you a completion report.
Copy the changed files from local commandcenter/ mirror into _generated/review/

**Step 9.** Glance at what's in _generated/review/
Does it look reasonable? Move it to _generated/approved/

**Step 10.** Upload the approved files to the live server via cPanel.
Move them to _generated/deployed/ on local once uploaded.

---

## AFTERNOON — 15 minutes

**Step 11.** Open legaisee.com/commandcenter/ in browser.
Quick check:
- [ ] Grand Lobby loads
- [ ] The module you just changed loads
- [ ] No PHP errors on screen
- [ ] No broken layout
- [ ] Buttons/AJAX work

**Step 12.** If something is broken:
Stop. Do not touch anything.
Open local ERROR_LOG.txt and write down the exact error.
Go to Claude: "Build failed. Error: [paste it]. Work order was: [link TODAY.txt]"
Follow Claude's recovery instructions.

**Step 13.** If everything works:
Celebrate. Move on to end of day.

---

## END OF DAY — 10 minutes

**Step 14.** Open local SESSION_LOG.txt.
Add today's entry at the TOP:

```
## YYYY-MM-DD — WO-###
Status: COMPLETE / PARTIAL / FAILED
Built: [what was completed]
Files deployed: [exact paths]
Blockers: [anything unfinished]
Notes for Claude: [anything unusual Claude should know]
```

**Step 15.** Update ACTIVE_TASKS.txt — mark completed items done,
move anything unfinished to BLOCKERS.txt if it's blocking next build.

**Step 16.** Upload these files to server:

```
SESSION_LOG.txt     → _operations/logs/
ACTIVE_TASKS.txt    → _operations/tasks/    (if changed)
BLOCKERS.txt        → _operations/tasks/    (if changed)
```

**Step 17.** Close everything. Done.

## TOTAL DAILY TIME

| Phase | Time |
|-------|------|
| Morning Claude session | ~10 min |
| Executor session | varies (30-90 min) |
| Browser QA check | ~10 min |
| End of day log update | ~10 min |
| **Total overhead** | **~30 min** |

The rest of the time is watching the executor work —
which you should do with one eye, not full attention.

---

## WHAT YOU NEVER DO

- Never edit governance files in cPanel directly (edit local, upload)
- Never let executor run without reading TODAY.txt first
- Never skip the SESSION_LOG update (Claude is blind next session if you do)
- Never deploy code that hasn't been through _generated/review/
- Never ask Claude to also write the code (Claude plans, executor builds)
