8-12-26_Legaisee Os Design Log
Summary
Running dated log of Master OS/UI design decisions for LEGAiSEE — build history for posterity and to keep design on track (companion to [[legaisee-os-vision]] and [[legaisee-command-center]])
Details
2026-08-04
Clarified Grand Lobby (current shell.php dashboard) is not a placeholder name for something good — it's just a card grid where cards display meaningless/non-real numbers, no unifying intelligence layer. Decision: trash it entirely, replace with the Master OS/UI design rather than improving it incrementally.
Core design principle adopted from existing governance doc (0608): interface should always answer "what, connections, why — never how." This is the filter for every Master OS/UI screen.
Proposed V1 Master OS/UI structure (five areas): Command View (replaces Grand Lobby), Case/Client View (drill-in per client — timeline, graph, findings, report, payment all in one place), Excavation Queue (intake → analysis → dig review as a pipeline), Vault & Delivery, System Health (small, tucked away — the one place "how" is allowed to live).
Locked in phased roadmap for the full North Star OS vision:
V1: Master OS/UI replacing Grand Lobby, visual match to legaisee.com/commissions.html, basic live client dashboard, simple "good morning" summary view — all wired to the already-complete backend (WO-A through WO-G).
V2: automated daily reports (AM system/client/suggestion), automatic AI prompts panel, full pipeline monitoring with error/efficiency flags, yearly review dossiers, compounding knowledge system, Authority Marketing System module, 3D graph upgrade (3d-force-graph, spin/rotate).
V3: autonomous digs (system decides where to look), self-building approved system changes, voice interface.
Research track (not phased, needs answers first): LLM cost modeling for dig automation/self-hosted LLM, artifact storage architecture (local vs. cloud vs. server-only), model-independence strategy for "outlast the tool" goal.
Clarified the CAMERA Authority System™ is NOT a build item for the OS roadmap — it's a personal on-camera coaching/training deliverable John teaches clients himself (tenth pillar of LEGAiSEE service methodology). Removed from phasing; filed in legaisee-services instead.
Confirmed: still in design phase, no coding started on Master OS/UI yet. Claude stays as architect/spec-writer; Kimi/GPT/Windsurf (whichever executor is available) builds the actual code once a spec is ready.
Locked: rail (left nav, "taskbar" equivalent) stays fixed/identical everywhere — same items, same order, always. The adaptive layer lives in the top bar instead (Mac menu-bar model), changing per section to match that section's verbs (e.g. Command's top bar = global search/notifications/customize; Clients/Cases' top bar = client search/filter/new case).
Locked: Command View is a customizable widget home screen. Permanent/fixed-position widgets: "Good Morning John" system-voice window, System Health corner. Swappable widgets: everything else (pipeline snapshot, revenue, recent activity, etc.), user can add/remove/rearrange.
Locked: widgets use size-aware tiers snapping to a grid (e.g. 1x1 compact stat, 2x1 wide list, 2x2 large graph/chart) rather than freeform drag-anywhere placement, to keep the polished/luxury feel.
Locked: Clients/Cases and each North Star pillar gets its own full-real-estate sub-dashboard (no shared space with Command's widgets), with layout matched to content type: graph-heavy (Excavation) = canvas-first minimal chrome; list/form-heavy (Clients/Cases directory) = table/filter-first; narrative/report-heavy (Vault) = document-first reading layout. All sub-dashboards share the same rail, same top-bar adaptive pattern, and same visual language (site colors/type/dark theme).
Locked: Command's "Recent Activity" widget is actually a persistent, append-only System Diary/audit log (like a GitHub commit history) — not an ephemeral feed. Purpose: answer "when did X happen" questions (e.g. client asks what day they sent a payment) by scrolling/filtering history rather than digging through modules. Design: entries are never individually edited or deleted (keeps the record trustworthy); only a full-log archive/reset action is allowed, gated by a double-confirm. Filterable by client/type/date range. Shows compact (last several entries) as the Command widget, expands to a full searchable view. Functionally treated as a third de facto permanent widget alongside Good Morning and Needs Your Attention, even though not hard-locked like System Health.
Locked: Command View is 3-tier. Tier 1 (fixed, system voice): Good Morning, Needs Your Attention, System Diary, System Health. Tier 2 (one overview tile per business-facing North Star pillar, always shown, click-through to full sub-dashboard for detail): Clients/Cases, Excavation, Dig Review, Knowledge System, Vault, Payments, Intake. Payments tile = business-wide aggregate only (last paid, outstanding/overdue) — per-client payment history/detail lives on each client's own page, not on Command. Infrastructure pillars (Tools, 3rd Party, Core Kernel) have no separate tiles, folded into System Health since they're not business-facing activity. Tier 3 (swappable utility widgets): Task Manager/Week View (non-urgent to-dos/calendar, separate from system-generated "Needs Your Attention"), Quick Client Contact Lookup (fast name-to-phone/email search for incoming calls).
Locked: Case/Client drill-in view uses a document-first reading layout (same rail + adaptive top bar as elsewhere; top bar here = client search/switcher, stage indicator, quick actions for send report/request payment). Fixed header block (always visible, no scroll): client name, current Kanban stage, Exhibit tier, next action, payment status chip. Below the header, six sections as tabs (not a stacked scroll): Timeline (client-scoped slice of the System Diary — stage changes, artifacts ingested, claims approved/rejected, emails, payments), Graph (that client's node graph embed, vis-network now/3D later, scoped to their case), Findings (the claims-review layer — approve/edit/reject happens here, not a separate page), Report (generated PDF(s) with version history), Payment (Stripe status/history, existing "Request Payment" button), Email (IMAP/SMTP thread panel matched to client/case — new scope).
