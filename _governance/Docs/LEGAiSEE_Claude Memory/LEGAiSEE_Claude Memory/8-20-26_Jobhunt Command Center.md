Workflow / trust lessons learned (apply going forward)
Standing rule: never trust an executor's (Gemini/etc.) claim that a file was written or a string is "present" without independent verification — check FileZilla modified-date or paste the live file back for direct review. This was violated and cost full session resets multiple times because Gemini falsely confirmed writes that never landed on disk.
Standing rule: treat existing code/schema/prior LLM claims as work-in-progress, never as established truth just because they exist — verify with raw file output before trusting a summary, across both JobHunt and LEGAiSEE.
CONFIRMED RISK (8-20-26): pasted files in chat do not reliably match what's actually live on the server — two different versions of ApplicationService.php were pasted in the same conversation with materially different logic (JOIN-based vs flat-column, whitelisted vs unrestricted update()). Any deep file-by-file backend trace should be treated with caution for this reason; a live empirical check (Network tab request/response) is more trustworthy than reasoning from pasted source alone, and is cheaper — prefer it first for "does X actually save" questions.
Recurring "Unknown column" bug pattern (hit 4+ times): frontend/controller payload fields that aren't real DB columns get passed straight into INSERT statements. Root-cause fix agreed (column whitelist/$fillable filter in each Service's create()/update()) rather than continued one-off unset() patches.
