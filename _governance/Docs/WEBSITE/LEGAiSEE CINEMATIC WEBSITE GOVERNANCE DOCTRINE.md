LEGAiSEE CINEMATIC WEBSITE GOVERNANCE DOCTRINE
Version 1.0 — FINAL / GOVERNING
System: LEGAiSEE
 Domain: legaisee.com
 Document Class: Creative + Experiential + Production Governance
 Status: GOVERNING
 Version: 1.0
 Supersedes: All prior informal cinematic-website direction and draft doctrine versions
 Primary Role: Establish the rules by which the cinematic LEGAiSEE website is conceived, designed, built, reviewed, modified, integrated, and maintained.

1. PURPOSE
The LEGAiSEE website is not to be treated as a conventional website with cinematic decoration.
It is to be conceived as a cinematic communication system transferred from film into an interactive browser environment.
The website must communicate the LEGAiSEE philosophy, methodology, authority, and value through:
narrative
composition
cinematography
spatial movement
controlled revelation
typography
visual metaphor
soundless visual rhythm
transitions
pacing
depth
interaction
information hierarchy
The objective is not merely to make the website "look cinematic."
The objective is to make the act of navigating LEGAiSEE feel cinematic.

2. PRIME DIRECTIVE
The final intended LEGAiSEE experience is the highest-order consideration in every decision.
No individual animation, component, page, asset, interaction, technical implementation, or requested fix may be evaluated exclusively at its local level.
Every decision must first be evaluated against the whole.
The governing question is:
Does this move LEGAiSEE closer to the intended final experience without damaging something else in the system?
A technically correct local change is still wrong if it damages the larger experience.
A visually impressive effect is still wrong if it does not serve the larger narrative.
A faster implementation is still wrong if it establishes an architecture that later prevents the intended experience.

3. MACRO-FIRST GOVERNANCE
3.1 The mandatory reasoning order
Every consequential decision follows:
VISION → SYSTEM → SITE → SCENE → SHOT → ELEMENT → IMPLEMENTATION
Never:
CODE → ELEMENT → SHOT → SCENE → SITE → SYSTEM → VISION
The second pattern is the principal mechanism by which AI systems fall into tunnel vision and create cascading problems.

3.2 Mandatory macro questions
Before making a consequential change, the responsible builder/AI must determine:
What is the final vision?
Where does this change fit within the complete website?
What scene does it belong to?
What shot or sequence does it affect?
What elements does it affect?
What previously established decisions does it depend upon?
What does it affect downstream?
What could it break upstream?
What global systems could it affect?
Does it establish a new pattern that other scenes must follow?
Is this a local correction or an architectural change?
Does it conflict with a locked decision?
Does it conflict with this Doctrine?
Does the resulting behavior improve the complete experience?
Only after those questions have been considered should implementation begin.

4. ANTI-TUNNEL-VISION RULE
A request such as:
"Fix the animation in this section."
must never automatically be interpreted as:
"Modify this block of code until it looks better."
Instead, the reasoning chain must be:
Element → Shot → Scene → Scene sequence → Site sequence → Global cinematic system → Final vision
The immediate problem is only one observation within that chain.
Therefore:
"Fix" does not mean "make the local thing work."
It means:
Restore the intended behavior while preserving system integrity.
If the local problem exposes a larger architectural problem, the larger problem must be identified rather than hidden with a local patch.

5. CHANGE LEVELS
Every meaningful change must be classified.
Level
Scope
Example
0

1

2

3

Levels 0–2 may normally be handled locally if they remain consistent with established decisions.
Level 3 requires scene-level evaluation.
Levels 4–5 require explicit recognition as architectural/vision changes and should not be silently introduced as "fixes."

6. SILENT SCOPE EXPANSION IS PROHIBITED
Macro-first thinking does not authorize uncontrolled redesign.
When investigating a local issue reveals another problem:
identify it
determine whether it actually affects the requested work
document the dependency
distinguish required remediation from optional improvement
escalate consequential architectural changes
The AI must not use a small task as an excuse to redesign unrelated portions of the system.

8. WHAT "CINEMATIC" MEANS
"Cinematic" does not mean:
dark website
black background

rotating model
random particles
lens flare

video background
parallax everywhere
videogame environment

8.1 The intended cinematic language
The LEGAiSEE visual language should draw from:
cinematography
investigative documentary
high-end editorial design
title design
architectural visualization
premium motion graphics
controlled lighting
photographic composition
information visualization
restrained luxury
The emotional character should communicate:
intelligence, depth, authority, discovery, precision, evidence, permanence, and significance.

9. CINEMATIC DOES NOT MEAN "3D WEBSITE"
Three-dimensional technology is an implementation capability, not the identity of the site.
The experience must never look like a videogame or technology demonstration simply because 3D rendering is available.
The governing question is:
What would a cinematographer do here?
not:
What cool 3D effect can we put here?
Spatial depth exists to support composition, storytelling, and meaning.

10. CINEMATOGRAPHY AS THE DESIGN LANGUAGE
The website should be understood as having a virtual camera.
The camera may conceptually perform:
Dolly — movement along the Z axis
Truck — movement along X
Pedestal — movement along Y
Pan — horizontal rotation
Tilt — vertical rotation
Roll — rotational orientation
Push-in / Pull-out — camera distance and/or lens relationship
Rack-focus equivalent — emphasis shifting between spatial layers
Lens/FOV changes
Depth changes
Framing changes
These concepts are creative abstractions.
The final technical implementation may use different technologies.
The Doctrine intentionally does not mandate a particular rendering engine.

11. SCROLL IS THE TIMELINE
This is one of the most important rules in the system.
Scroll is not an animation trigger.
Scroll represents the position of the viewer within the cinematic timeline.
Conceptually:
Scroll Position = Playhead Position
Therefore the system should behave more like an editing timeline than a collection of webpage triggers.

11.1 Continuous state
A cinematic action should be capable of being:
advanced
paused
reversed
scrubbed
partially completed
revisited
jumped through
The system must not depend on:
enter viewport → play animation once
as its fundamental cinematic model.

11.2 Deterministic state
If the viewer moves from timeline position 31% to 67%, the system must resolve the scene to the correct state at 67%.
It must not require the viewer to have previously watched every animation between those points.
This is essential to the "scrubbing a film" metaphor.

12. THE VIEWER EXPERIENCE
The intended mental model is:
The viewer is sitting on a camera dolly, looking through the viewfinder, and using the scrollbar as the editing/playback control.
The viewer should feel that the website is moving around them rather than simply revealing stacked webpage sections.
The experience may include:
foreground elements passing camera
background environments shifting
objects moving independently
typography entering/exiting spatial planes
camera movement
depth changes
transitions between environments
objects appearing through controlled revelation
visual relationships forming over time
information becoming understandable as the camera progresses

13. SCENES
A scene is the fundamental production unit of the LEGAiSEE website.
A public page/concept is treated as a scene.
A scene may contain:
multiple shots
multiple spatial environments
multiple information states
multiple objects
multiple camera movements
multiple transitions
multiple narrative beats
A scene is therefore not merely a <section> in HTML.

Cinematic purpose

Motion purpose
What changes as the playhead advances?
Transition purpose
How does the scene enter and leave?
Business purpose
Why does this scene matter to LEGAiSEE?

15. SCENE-BY-SCENE PRODUCTION
The website should be developed as a sequence of independently reviewable cinematic scenes.
The production process is:
Design Scene → Prototype Scene → Review Scene → Revise Scene → Lock Scene → Integrate Scene
The complete website is then assembled as a cinematic sequence.
This allows individual scenes to be perfected without losing sight of the larger film.

16. GLOBAL EDIT
Individual scenes do not exist in isolation.
After scenes are approved, the entire website becomes an editorial sequence.
The global edit evaluates:
pacing
continuity
rhythm
visual progression
camera continuity
transitions
tonal progression
information density
emotional progression
CTA placement
navigation
performance
A scene that works beautifully by itself may still require modification if it damages the complete sequence.

17. TRANSITIONS ARE PART OF THE STORY
Transitions must not merely hide page changes.
A transition communicates continuity.
The system should determine whether the viewer experiences:
movement into another environment
transformation
dissolution
discovery
temporal progression
spatial travel
conceptual connection
contrast
interruption
A transition that looks impressive but has no narrative purpose is suspect.

18. CONTINUITY
The site should have a recognizable cinematic grammar.
Across scenes, the viewer should sense that:
This is one film, not a collection of unrelated experiments.
Continuity may come from:
typography
lighting language
camera behavior
material language
motion curves
color progression
spatial logic
recurring visual motifs
transition language
soundless rhythm
compositional discipline

19. VISUAL LANGUAGE
The visual system should evolve beyond generic:
black + gold = luxury
Black/gold may remain part of the identity, but gold must carry meaning.
The preferred direction is closer to:
graphite / black / steel / mineral / restrained gold
rather than ornamental black-and-gold luxury.
Gold may signify:
discovery
authority
signal
significance
evidence
value
the recovered artifact
the thing that matters
It should not exist merely because gold looks expensive.

20. CONTROLLED REVELATION
LEGAiSEE is fundamentally about discovering what is beneath the surface.
Therefore the visual system should exploit:
hidden → revealed
fragmented → connected
noise → signal
unknown → understood
surface → depth
raw → refined
evidence → conclusion
history → authority
These are creative principles, not mandatory literal animations.
The metaphor should be adapted to each scene.

21. TYPOGRAPHY
Typography is an active cinematic element, not merely page decoration.
It may function as:
title card
environmental object
foreground element
spatial layer
annotation
evidence label
chapter marker
narrative statement
visual anchor
Typography should be treated with the same compositional care as a film title sequence.
Effects such as metallic treatment, depth, lighting, extrusion, blur, masking, and spatial placement should be used only when they support the scene.

22. ASSET PHILOSOPHY
The browser should reproduce behavior, not unnecessarily reproduce exported film layers.
The system must avoid the assumption:
After Effects composition = dozens of PNG/SVG layers downloaded by the browser.
That approach can create unnecessary:
bandwidth
memory use
decoding cost
HTTP requests
GPU texture pressure
mobile performance problems

22.1 Browser-native whenever practical
Prefer browser-generated or procedural representations for:
typography
gradients
lighting
shadows
geometry
lines
particles
simple textures
masks
transitions
camera movement
spatial transforms
effects that can be calculated efficiently

22.2 Use downloaded assets when they contain unique visual information
Examples:
photography
unique textures
artwork
photographic environments
irreplaceable imagery
highly detailed material information
The question is not:
"Can this be exported from After Effects?"
The question is:
"Does this asset contain information the browser cannot efficiently recreate?"

23. NO VIDEO-DEPENDENT CINEMATIC MOTION
The primary cinematic motion system must not depend on pre-rendered video.
The core experience must be controlled by browser-side state.
This preserves the fundamental requirement:
Every important visual element is capable of responding to the cinematic timeline rather than simply displaying a video frame.
Video may only be introduced as a separate, explicitly justified creative decision.
It is not the default mechanism for simulating cinematic scroll.

24. VISUAL COMPLEXITY ≠ ASSET WEIGHT
A visually sophisticated scene does not necessarily require a massive collection of assets.
The system should seek the highest ratio of:
Perceived cinematic richness / actual computational and bandwidth cost
This is achieved through intelligent division between:
geometry
code
CSS
SVG
WebGL/canvas where appropriate
typography
optimized imagery
procedural effects

25. PERFORMANCE IS A CREATIVE CONSTRAINT
Performance cannot be treated as a cleanup task performed after the design is finished.
Performance affects the cinematic experience directly.
A beautiful animation that produces:
dropped frames
input lag
stuttering
excessive memory use
long loading
mobile failure
is not a successful cinematic experience.
Therefore:
Performance is part of cinematography.
The creative solution must be designed within a realistic performance budget.

26. RESPONSIVE CINEMATOGRAPHY
Responsive behavior must not mean:
Desktop composition shrunk until it fits mobile.
Mobile may require a different cinematic interpretation.
The system may alter:
camera path
framing
depth
object count
timing
spatial relationships
typography scale
transition complexity
environmental detail
effects
The objective is:
Preserve the cinematic intention, not necessarily the identical implementation.

27. ACCESSIBILITY AND REDUCED MOTION
Accessibility is part of the experience architecture.
Reduced-motion behavior must not simply mean:
"Turn everything off."
Where practical, the alternative should preserve:
narrative order
information hierarchy
scene identity
visual meaning
navigation
comprehension
Motion can be reduced while the story remains intact.

28. NAVIGATION AND PAGE STRUCTURE
The cinematic experience may feel like one continuous film even though the website retains separate pages/URLs.
This provides the ability to preserve:
SEO
direct linking
browser history
navigation
accessibility
shareable URLs
conventional web expectations
The visual continuity must not require destroying useful web architecture.

29. CREATIVE TREATMENT VS. GOVERNANCE
The Doctrine governs how decisions are made.
It does not prescribe the exact creative treatment of every scene.
Therefore the Doctrine should not permanently define:
exact camera coordinates
exact scene durations
exact animations
exact asset filenames
exact technical framework
exact folder structure
exact number of particles
exact transition implementation
exact scene count
exact JavaScript architecture
Those belong downstream.
The hierarchy is:
Doctrine = rules
Treatment = creative interpretation
Scene Specification = scene design
Work Order = production instructions
Code = implementation

30. TECHNOLOGY MUST SERVE THE CINEMATIC REQUIREMENT
No technology is sacred.
Three.js, WebGL, GSAP, CSS, SVG, Canvas, Web Components, or other technologies may be used where appropriate.
The Doctrine does not select the technology.
The cinematic requirement selects the technical approach.
The governing question is:
What is the simplest reliable technology capable of producing the required cinematic behavior at acceptable performance?

33. AI MUST UNDERSTAND THE SYSTEM BEFORE EDITING THE SYSTEM
Before modifying an existing implementation, AI must establish:
Current state
What exists now?
Intended state
What is supposed to exist?
Relevant scene

Dependencies

Consumers
What depends upon this code?
Global systems

Locked decisions

34. EXISTING CODE IS EVIDENCE, NOT AUTOMATIC AUTHORITY
Existing prototypes, experiments, and prior implementations may contain valuable work.
They must not automatically become canonical simply because they already exist.
Existing work should be classified as:
retained
adapted
replaced
experimental/reference
deprecated
A prototype demonstrates possibility.
It does not automatically establish architecture.

37. SCENE LOCK
A scene becomes LOCKED only when:
creative direction is approved
visual identity is approved
cinematic behavior is approved
narrative purpose is satisfied
technical implementation is stable
responsive behavior is acceptable
accessibility behavior is acceptable
performance is acceptable
transitions are acceptable
Once locked, a scene should not be casually altered.

37.1 Locked scene changes
A locked scene may be changed when:
a verified defect exists
integration exposes a genuine dependency
performance requires modification
accessibility requires modification
responsive behavior requires modification
a higher-level system change requires it
the Director explicitly requests a revision
A locked scene must be re-evaluated after consequential modification.

38. REGRESSION GOVERNANCE
After a consequential change, testing must extend beyond the immediate target.
At minimum evaluate:
Changed Element → Current Shot → Current Scene → Previous Scene → Next Scene → Global Cinematic System
The greater the change level, the broader the regression scope.
This prevents:
"I fixed Scene 5 and accidentally broke Scene 2."

40. STOP CONDITIONS
The AI/builder must stop and escalate rather than blindly proceeding when:
The request conflicts with this Doctrine.
A locked scene must be substantially changed.
A local fix requires architectural modification.
The intended creative result cannot be technically achieved with acceptable quality.
Performance becomes unacceptable.
The requested solution requires an unapproved asset pipeline.
A change unexpectedly affects multiple scenes.
Existing decisions contradict one another.
The requested result would damage the global sequence.
The system's current state is insufficiently understood.
The requested change would redefine the website's core visual identity.
The final vision cannot be preserved.
Stopping is preferable to silently introducing architectural drift.

41. NO TECHNOLOGY-DRIVEN DESIGN
The process must never begin with:
"Let's build a Three.js site."
or:
"Let's add WebGL."
or:
"Let's use GSAP everywhere."
Technology is downstream.
The process begins with:
What must the viewer experience?
Then:
What cinematic behavior creates that experience?
Then:
What technical architecture can deliver it reliably?

42. NO EFFECT FOR EFFECT'S SAKE
Every major effect must have a reason.
Ask:
What does this communicate?
What does it reveal?
What does it emphasize?
What does it transition?
What does it make the viewer feel?
What information does it clarify?
If the answer is simply:
"It looks cool."
the effect requires reconsideration.

43. INFORMATION MUST REMAIN LEGIBLE
Cinematic presentation must never overpower the message.
LEGAiSEE's content is sophisticated.
The site must not become an art installation that forces visitors to decipher basic business information.
The cinematic layer exists to increase comprehension and perceived authority, not decrease it.

44. BUSINESS PURPOSE REMAINS PRIMARY
The website is ultimately a business instrument.
Every scene must contribute to some combination of:
understanding LEGAiSEE
establishing authority
differentiating LEGAiSEE
increasing perceived value
explaining the methodology
demonstrating intellectual rigor
establishing trust
attracting appropriate clients
moving qualified visitors toward engagement
Cinematic spectacle without business purpose is not success.

45. THE SITE IS A FILM, BUT IT IS STILL A WEBSITE
The cinematic metaphor must never eliminate fundamental web requirements.
The finished system must remain:
navigable
understandable
linkable
responsive
accessible
performant
maintainable
indexable where appropriate
usable
The goal is:
A website that behaves like a film.
Not:
A film that happens to be trapped inside a website.

48. FINAL VISION TEST
Before accepting a major change, ask:
If we look at this decision from the perspective of the complete finished LEGAiSEE website, does this belong there?
Then ask:
Does it make the experience feel more like the intended LEGAiSEE film?
Then:
Does it preserve everything that already works?
Then:
Does it create a dependency or precedent that affects future scenes?
If the answer is uncertain, the decision is not ready to become canonical.

49. ACCEPTANCE CRITERIA FOR THE FINISHED WEBSITE
The finished website succeeds when a visitor does not primarily think:
"This is a website with animations."
Instead, the desired response is closer to:
"I'm moving through something."
The viewer should experience:
intentional camera movement
cinematic pacing
spatial depth
controlled revelation
coherent visual storytelling
meaningful transitions
sophisticated typography
restrained visual luxury
information becoming progressively clearer
a unified sequence rather than disconnected pages
The website should feel:
expensive without being ornamental.
technical without looking like a tech demo.
cinematic without being a video.
three-dimensional without looking like a videogame.
luxurious without relying on cliché black-and-gold decoration.
complex without becoming confusing.
immersive without sacrificing usability.

50. THE ULTIMATE GOVERNING PRINCIPLE
LEGAiSEE is built around the idea that meaningful authority is not manufactured from nothing.
It is:
discovered, excavated, verified, reconstructed, and restored.
The website should embody that same philosophy.
The visual experience should not merely tell the visitor that LEGAiSEE uncovers buried strategic value.
The experience itself should make the visitor feel the process of discovery.
The viewer begins with incomplete information.
The system reveals relationships.
Fragments become evidence.
Evidence becomes structure.
Structure becomes understanding.
Understanding becomes signal.
Signal becomes authority.
That progression is the cinematic spine of the entire website.

51. FINAL GOVERNANCE STATEMENT
LEGAiSEE's cinematic website is one continuous interactive cinematic system composed of independently producible scenes.
Scroll is the playhead.
The browser is the medium.
The camera is the primary narrative instrument.
Motion is controlled cinematography, not decoration.
Scenes are production units, not merely webpage sections.
Assets support the experience; they do not define the architecture.
Technology serves the creative requirement.
Performance is part of the creative requirement.
The website and application remain separate experiences.
AI performs the heavy analytical and technical work but cannot silently redefine the creative vision.
Every consequential decision begins at the macro level and works toward the micro level.
No local fix is accepted if it damages the larger system.
No scene is considered complete until it survives both local review and global integration.
No implementation becomes canonical merely because it already exists.
And no individual effect, page, scene, or technical decision is more important than the final LEGAiSEE experience.
VISION → SYSTEM → SCENE → SHOT → ELEMENT → CODE
That is the governing order.
